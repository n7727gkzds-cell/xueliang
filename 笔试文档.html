1. 挑战内容

我做的是 Forge，一个对话式的应用生成工具。一句话描述想要什么，它拆解需求、生成一个完整可用的网页，右侧实时预览，可以继续对话改，满意了发布成一个网址。

动手前我把 Atoms 的帮助文档读了一遍，把里面的产品要求整理成清单：项目简报、参考附件、先定一个小目标、给出具体改进建议、发布和更新线上版本。后面开发基本照着这份清单逐个落地。

几个核心点

  • 生成由四个智能体协作完成，规划、设计、构建、评审各管一段，每个角色的输出实时打在对话里，过程看得见。
  • 预览边生成边渲染，代码流出多少就渲染多少，不白屏干等。
  • 默认走内置本地引擎，内置 8 类应用模板，零配置就能演示，任何时候打开都有东西看，不会停在报错页。也支持接 OpenAI 兼容的云端模型（MiMo 等），经本地 Node 代理转发、密钥不落前端；本演示版默认关闭，需要时改一个开关就能开。
  • 要先登录才能进工作台，可以自己注册，也可以用测试账号直接进。登录后项目简报、每个版本的代码、发布记录都存在服务端，换台电脑登录还能接着改；不登录也能用，数据留在本机浏览器。

开发用 WorkBuddy（AI 编程 Agent）协作完成，写完用 Playwright 加真实 Chromium 跑了 34 项端到端检查，全部通过，0 控制台错误。

2. 提交方式

以下是简要说明文档。

实现思路与关键取舍

模型接入走本地代理，没让浏览器直连

直连有两个绕不开的问题：CORS 会拦，API Key 也容易暴露在前端请求里。所以加了一个本地 Node 代理，Key 只存在浏览器 localStorage 里，请求经代理转发。协议统一用 OpenAI 兼容格式加 SSE 流式，换厂商不用改代码。

做了本地引擎兜底

评估的人不一定配 Key，网络也可能出问题，所以内置了规则引擎，按意图套模板生成完整页面。模型调不通就自动切过去，演示不中断。

发布改成了真实可访问的地址

上一版生成的地址换个浏览器就打不开，这版让服务端把当前版本写成静态页面，返回 /p/<slug>，任何人打开都能看到。再点一次发布就是更新线上版本，地址不变。

数据持久化做了两层

登录后项目简报、每个版本的代码、发布记录都存服务端，每个用户一个 JSON 文件，换台电脑接着改；不登录退回本机 localStorage，功能照常跑。密码用 scrypt 加盐哈希，登录态是 HttpOnly cookie。没引数据库是因为这个体量文件存就够了，部署也省事。

版本管理是后补的

最初只有生成和预览，对照 Atoms「更新线上版本」的要求加了版本历史。发现光能回滚还不够、改了什么看不出来，又加了行级 diff：选两个版本能看到新增删除了哪些行；代码面板里也能直接改代码，改完存成新版本。

迭代要看得见变化

第一版里点「让营业时间更醒目好找」，新旧版本代码一模一样，等于白改。后来给本地引擎补了微调规则，这类意见现在会真的改动 HTML，并且明确告诉你改了哪几处。

测试时才发现的几个问题

这几个都是跑端到端验证时暴露出来的，本地开发阶段不会碰到。

点不同推荐入口，生成的页面结构完全相同，只有配色不同

原因是生成过一次之后，之后所有输入都被当成迭代请求，而迭代会继承上一版的模板类型。修法是加了一层意图判定：先识别微调信号（标题、字号、颜色、改成、加上这类），命中就判为迭代；只有句子里真的出现了另一类应用的关键词（看板、商城、博客、作品集），才判为换一个应用重新生成。判定逻辑单独跑了 13 条用例，又连点四个入口核对结构确实不同，同时回归确认「标题再大一点」不会误触发。

远程桌面上整页一直闪，本机打开完全正常

先排除了代码问题，布局抖动为 0、文档高度恒定、没有自发请求。真正原因是背景那两团装饰光斑：直径近千像素、90px 模糊、固定在屏幕上做 19 秒和 23 秒的无限循环漂移。模糊是逐像素运算，本机 GPU 能跑满 60 帧，但远程桌面要把画面逐帧压缩成视频流传过去，合成追不上编码就闪了。现在检测到远程桌面会话、系统开了「减少动态效果」、或者设备核心数很少时会自动降载，关掉大面积模糊和常驻动画，毛玻璃也换成不透明底色；也支持网址后加 ?lite=1 强制开启。光斑只是不漂移，视觉上基本看不出差别。

线上同步一直显示失败

抓包发现读取正常，只有写入被拦，返回的不是自己的接口错误而是云平台的「WAF 拦截页面」。逐项对比后定位到触发条件：只要请求体里出现 <script> 这个字面量就被判定成 XSS 注入拦掉，而生成的页面本来就带 <script>，所以同步必然失败；把同样内容全部转义成纯文本照样被拦，说明匹配的是这个标签模式本身，不是脚本内容。解法是把请求体统一 base64 编码再发，服务端识别标记后解码。这个问题只在部署后被别人访问时才暴露，本地开发测不出来。

当前完成程度

功能上完成的

  • 注册、登录、退出，密码加盐哈希，登录态 HttpOnly cookie，自带测试账号
  • 服务端数据持久化，换设备可续；不登录时降级存本机
  • 发布生成真实可访问的 /p/<slug> 地址，再发布即更新线上版本
  • 四智能体协作生成，每个带可展开的结构化产出物和耗时
  • 流式实时预览，桌面、平板、手机三档设备框
  • 工作台自身也做了响应式：平板上下分栏，手机上对话和预览全屏切换，登录页在手机上铺满整屏
  • 代码面板支持查看、直接编辑（存为新版本）、版本间行级 diff
  • 版本历史：回滚、改名、对比
  • 无后端也能登录：file:// 或离线打开时启用纯前端本机账号，发给别人、别人电脑打开同样能注册登录使用
  • 能分清「换一个应用」和「改当前应用」，新需求换模板重新生成，微调意见走增量修改
  • 远程桌面和弱设备下自动降载，演示时不再闪屏
  • 演示状态已预置：测试账号里放好了生成好的应用和版本历史，登录后直接看到成品、已发布地址和可回滚的历史版本
  • 项目简报、图片附件作为设计参考（模型不支持时自动降级为纯文字）
  • 端到端 34 项检查全部通过，0 控制台错误

没做、或者只做了一半的

  • 产物还是单文件 HTML，没有工程化拆分，在线编辑也是改整份代码，不是组件级
  • 智能体是编排出来的叙述流程，没接真正的 Agent 框架做工具调用
  • 发布页没有权限控制，拿到链接的人都能看，也没有自定义域名
  • 账号是文件存储，量大了得换数据库，还要补邮箱验证和找回密码

如果继续投入

先做产物工程化。单文件演示够用，但真要迭代一个复杂应用代码会膨胀到难维护。拆成多文件结构，编辑粒度降到组件级，同时对生成质量加约束，比如按组件输出、每次只改受影响的部分。

然后是账号体系。现在文件存储够用但不正规，换成数据库，补上邮箱验证和找回密码，再加发布页的访问权限（私有链接、有效期、访问统计）。

再往后是让评审智能体真正干活：自动截图对比、检查移动端适配和可访问性，给出能执行的修改意见，而不是现在这种基于规则的建议。

多人协作放最后。评论、协同编辑这些在单机场景下收益最小，前面几步不做完它也做不起来。
